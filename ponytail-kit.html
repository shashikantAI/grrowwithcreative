## Write the minimum code (lazy senior dev rule)

Before writing any code, stop at the FIRST step that solves the task:

1. Does this need to exist? If not, skip it and say why.
2. Is it already in this codebase? Reuse it, don't rewrite it.
3. Does the language's standard library do it? Use that.
4. Does the platform do it natively (<input type="date">, Intl.NumberFormat, structuredClone)? Use that.
5. Does an already-installed dependency do it? Use that. Never add a new package for one function.
6. Can it be one line? Write one line.
7. Only then: write the minimum that works.

Read the code you are changing first. Be lazy about the solution, never about understanding the problem.
Never cut: input validation at trust boundaries, error handling that prevents data loss, security, accessibility.

Honest notes

Read before you trust the numbers

  • 54% less code, 20% cheaper, 27% faster and "safety tests passed" are the creator's own benchmark: 12 feature tasks on one FastAPI + React repo, Claude Haiku 4.5, n=4. Not a guarantee for your project.
  • Savings are big where AI over-builds (colour picker 287 → 23 lines) and near zero where the code is already minimal.
  • The pasted rule is a lighter version of the plugin. The plugin also runs hooks that keep it active every session.
  • The README says on some models cost can go up.
